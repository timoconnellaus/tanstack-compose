# Roadmap — peeling the onion

Each slice is self-contained with its own acceptance file and tests. A slice is
done when its criteria pass and every earlier slice's criteria still pass. Work
is not pulled forward from a later slice.

| #   | Slice                                                                                                                                                                                                | Proves                                                                                                                              | Acceptance                                                   | Status      |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ----------- |
| 1   | **Kernel** (`@tanstack/compose`): client, plugins, context and deps, cleanup, status, options, middleware and events, plugin list reconciliation, inspection                                          | A plugin can be added, removed, replaced and reconfigured while the application runs, with nothing left behind                      | [`docs/acceptance/kernel.md`](./docs/acceptance/kernel.md)   | done        |
| 2   | **Agent layer** (`@tanstack/compose-agent`): context keys for model, tools, prompt and session; the loop plugin; a scripted model for tests; one real model provider package                          | An agent whose capabilities are plugins, where every request and tool call is an action other plugins can wrap                      | [`docs/acceptance/agent.md`](./docs/acceptance/agent.md)     | in progress |
| 3   | Self-modification: plugins giving the agent tools to list, enable, disable, configure and add plugins in its own client                                                                              | The application edits itself safely                                                                                                 | [`docs/acceptance/self-modification.md`](./docs/acceptance/self-modification.md) |             |
| 4   | React adapter (`@tanstack/react-compose`) + example app: a chat surface and a composer panel that shows the plugin list changing live                                                                 | The kernel and agent are usable from a UI, and a human can watch and edit what the agent does to itself                             | `docs/acceptance/react.md`                                   |             |
| 5   | Devtools (`@tanstack/compose-devtools`): instances, unmet deps, held resources, middleware/event trace                                                                                                 | Everything the kernel knows is visible                                                                                              | `docs/acceptance/devtools.md`                                |             |
| 6   | Hosts: the host contract in core with the in-process host; `@tanstack/compose-worker` (Web Worker + Hardened JS) for Bun, Node and browsers; `@tanstack/compose-cloudflare` (Dynamic Workers) for SaaS | Agent-written plugins run in isolation, behind the same instance interface, on every runtime the kernel supports                    | [`docs/acceptance/hosts.md`](./docs/acceptance/hosts.md) |             |
| 7   | Scoped clients: child clients per route/request with their own context; TanStack Router and Start integration                                                                                        | Per-scope worlds                                                                                                                    |                                                              |             |
| 8   | Hardening: HMR for plugins in dev, persistence of plugin-list edits, size and performance budgets                                                                                                     | Ready for others to build on                                                                                                        | `docs/acceptance/hardening.md`                               |             |

Terms are defined in [`CONTEXT.md`](./CONTEXT.md); decisions in [`docs/adr/`](./docs/adr).
