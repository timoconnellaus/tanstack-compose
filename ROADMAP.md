# Roadmap — peeling the onion

Each slice is self-contained with its own acceptance file and tests. A slice is
done when its criteria pass and every earlier slice's criteria still pass. Work
is not pulled forward from a later slice.

| #   | Slice                                                                                                                                                                                   | Proves                                                                                                                | Acceptance                                                                                                            | Status |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------ |
| 1   | **Kernel** (`@tanstack/compose`): client, plugins, context and deps, cleanup, status, options, middleware and events, plugin list reconciliation, inspection                             | A plugin can be added, removed, replaced and reconfigured while the application runs, with nothing left behind        | [`docs/acceptance/kernel.md`](./docs/acceptance/kernel.md)                                                            | done   |
| 2   | **Agent layer** (`@tanstack/compose-agent`): context keys for model, tools, prompt and session; the loop plugin; a scripted model for tests; one real model provider package             | An agent whose capabilities are plugins, where every request and tool call is an action other plugins can wrap        | [`docs/acceptance/agent.md`](./docs/acceptance/agent.md)                                                              | done   |
| 3   | **Self-modification**: the host contract and in-process host in core; tools giving the agent list, enable, disable, configure, add-from-catalog, and write/read/rewrite plugin source   | The application edits itself safely, including its own code                                                           | [`docs/acceptance/self-modification.md`](./docs/acceptance/self-modification.md), [`hosts.md §A`](./docs/acceptance/hosts.md) |        |
| 4   | **Cloudflare host** (`@tanstack/compose-cloudflare`): agent-written plugins run in Dynamic Workers behind the same instance interface                                                    | Self-modification is safe to offer in SaaS: written code is isolated, limited and fully torn down                     | [`docs/acceptance/hosts.md`](./docs/acceptance/hosts.md) §B, §D, §E                                                   |        |
| 5   | React adapter (`@tanstack/react-compose`) + example app: a chat surface and a composer panel that shows the plugin list changing live                                                    | The kernel and agent are usable from a UI, and a human can watch and edit what the agent does to itself               | `docs/acceptance/react.md`                                                                                            |        |
| 6   | Devtools (`@tanstack/compose-devtools`): instances, unmet deps, held resources, middleware/event trace                                                                                    | Everything the kernel knows is visible                                                                                | `docs/acceptance/devtools.md`                                                                                         |        |
| 7   | Portable host (`@tanstack/compose-worker`): Web Worker + Hardened JavaScript for Bun, Node and browsers                                                                                  | The same isolation on every runtime the kernel supports                                                               | [`docs/acceptance/hosts.md`](./docs/acceptance/hosts.md) §B, §C                                                       |        |
| 8   | Scoped clients: child clients per route/request with their own context; TanStack Router and Start integration                                                                           | Per-scope worlds                                                                                                      |                                                                                                                       |        |
| 9   | Hardening: HMR for plugins in dev, persistence of plugin-list edits, size and performance budgets                                                                                        | Ready for others to build on                                                                                          | `docs/acceptance/hardening.md`                                                                                        |        |

Terms are defined in [`CONTEXT.md`](./CONTEXT.md); decisions in [`docs/adr/`](./docs/adr).
